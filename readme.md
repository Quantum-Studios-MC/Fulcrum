Fulcrum is a modding library built for organizations or teams that maintain mods across multiple Minecraft versions. The core problem it solves is that right now if you want your mod on 1.7.10, 1.12.2, 1.20.1 and 1.21.1, you basically need four different developers who each know their version inside and out. That's a lot of tribal knowledge and it makes onboarding new people really painful.
Fulcrum fixes this by giving everyone a single API to code against. You write your mod once in the Common project using interfaces like IBlock and IItem, and Fulcrum handles translating that into whatever the underlying version actually needs. A new dev on your team only needs to learn Fulcrum, not four different modding environments.
The template ships with a simple gradle.properties where you fill in your mod name, id, author and version once, and the build system handles packaging everything correctly for each target. The version specific subprojects are there if you need to do something advanced like mixins, but for the vast majority of mod content you never touch them.
On the API side the philosophy is that you should be writing logic not configuration. So instead of maintaining a pile of blockstates.json and models/items.json files, you describe everything in code and Fulcrum generates whatever JSON the version needs underneath. Blockstates get translated to metadata on legacy versions automatically, common shapes like stairs and slabs are pre built so you just implement the interface, and the 16 value metadata limit on older versions is handled transparently.
The name Fulcrum comes from the lever analogy. You apply a small amount of effort on one end, and the library carries the load of cross version compatibility on the other.
